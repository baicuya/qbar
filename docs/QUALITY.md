# Qbar 体验整改

2026-09-29：用户明确指出当前产品质量和图标设计不合格。停止上架准备，优先保证核心操作可靠。

## 已确认的问题

- macOS 26 的 NSStatusItem 本地窗口位置可能是陈旧值，启动时曾将全部图标误判为始终隐藏。现改为以同一份 CG 窗口快照计算图标与分隔符的位置。
- 旧版将图标与窗口的初始错误对应长期缓存，导致名称串位。现移除该缓存，重新按当前几何位置和明确标题匹配。
- 匿名托管窗口在沙盒中缺少真实应用身份。自定义名称只能改善显示；匿名窗口 ID 在宿主重启后变化，跨重启恢复尚未解决。
- 从右侧移动到刘海左侧成功后，回移曾连续失败。现加入有效命中区域计算和刘海目标位置拦截；不能称为完整刘海屏支持。
- 辅助功能按下菜单后可能返回超时，旧版补发点击会关闭已打开的菜单。已增加菜单打开状态判断。
- 设置列表错误使用菜单栏截图并加黑色底块，导致图标缩小、失真。现将应用图标与菜单栏快照分开保存：列表使用真实应用图标和系统符号，浮窗保留菜单栏快照。
- 截取不可见图标会等待超时，影响刷新速度。现只更新屏幕上可见窗口的快照，批量发布结果。
- 自定义原生主菜单被 SwiftUI 替换，编辑快捷键不可靠。已使用 SwiftUI Commands；自动化粘贴仍出现超时，须继续核对，不能标记验收通过。
- 旧版启用管理时默认分隔符位于右侧，大量现有图标立即被收纳。新版首次启用从左侧分隔符开始，迁移后管理默认关闭。
- 早期测试残留很多未运行图标规则，需要提供可恢复的清理方式。

- App Sandbox 构建编译，签名 entitlements 已核对。
- 本地版 A 测试图标在显示/收纳间移动；浮窗激活原菜单；延迟归位。
- 沙盒版将 A 从收纳区移到显示区；CG 点击打开测试程序原生菜单。
- 沙盒版将 A 移入始终隐藏区。反向移动的刘海边缘案例失败，未通过。
- 启动折叠前获取了 17/17 菜单栏图标快照。
- 配置测试覆盖格式、大小、归一化、快捷键冲突、排序、别名向后兼容。

## 图标整改

- 用户明确指出列表图标问题；移除列表黑底截图、重复的应用名称副标题，并过滤临时 System Status Item Clone 窗口。
- 按用户最新参考改为蓝青渐变、白色窗口与顶部菜单栏造型，撤回容易被误认为搜索的 Q 字标。

## 追加 bug 检查与修复（2026-09-29）

- 刷新：刷新中的新请求原先会丢失；现在合并排队，丢弃过期扫描，等待移动完成后重新扫描。
- 名称：改名、导入后立即更新列表；保留系统原始名称，用于 Siri 等固定项目的图标与移动限制判断。
- 改名表单：实机复现第二次打开时初值变空、保存未生效。改为独立状态的 sheet，已实测连续改名、重开初值、清空恢复名称成功。
- 布局：固定系统图标不能通过拖放绕过限制；应用导入布局前明确拒绝固定图标的非法分组；取消待应用布局同时还原当前项目的分组和顺序。
- 拖放：使用私有项目类型传递当前 ID，避免取消拖放后遗留旧 ID，后续外部文本误触移动。
- 浮窗：设置变更时取消旧收起计时器，计时触发前重查开关、移动状态及鼠标位置；显示模式切换时关闭不适用的浮窗。
- 移动与归位：取消操作后停止后续点击和偏好写入；鼠标已按下时保证释放；延迟归位避开正在进行的移动，保留失败项目的归位记录。

验证：19 项测试（11 项配置、8 项运行时）全部通过；通用 Release 构建与安装签名校验通过。新版已安装到 `/Applications/Qbar.app`。

界面检查：Siri 改名后保留闪光图标及禁止移动菜单；连续改名和清空恢复通过。自动收起的鼠标停留场景未获得可靠界面结果，仅策略单测通过，不算完整验收。

最终恢复：管理关闭，自动收起关闭，等待时间 3 秒，聚合浮窗，透明菜单栏图标；全局快捷键为空，无测试别名。透明图标为本轮开始时用户当前选择，未改回早期默认图形。

仍未解决：拥挤刘海菜单栏的收纳目标定位；全局快捷键触发仍未通过自动验证。上述限制继续按 `AUDIT-2026-09-29.md` 跟进，不因本轮测试通过而视为已解决。

## “应用布局”禁用修复

用户在管理关闭时已将搜狗输入法、Docker 放入收纳区，但按钮因 `!managementEnabled` 被禁用。改为按钮允许点击，由 `requestApplyLayout()` 先保留待应用状态、通过原有权限和冲突检查开启管理，再派发应用操作；页面明确提示此行为。移动进行中或无图标时继续禁用。

21 项测试通过，通用 Release 构建、签名校验及安装完成。实机确认：管理关闭时“应用布局”已可点击，两个收纳分组保留。本轮未触发真实批量移动，不将按钮恢复等同于刘海定位问题已解决。

## 系统项目与图标显示（2026-09-29）

- “音频与视频控制”从菜单栏扫描和旧配置中排除；其他固定系统项目留在“始终显示”。已在本机确认列表不再出现该项目，配置中的旧规则也被清理。
- 设置列表里的应用统一读取所属 `.app` 的原始图标。新启动的应用由工作区通知触发扫描，按同一规则取图；系统项目使用对应系统符号。ClashX Pro 的网速文字不再混入图标。
- 收纳浮窗改为随内容收缩的纯图标网格，图标来自应用本身；名称保留在鼠标悬停提示和辅助功能标签中。三项布局下实机检查了搜狗输入法、Docker Desktop、UU远程的显示。
- 23 项测试通过，Release 通用构建和签名校验通过，已安装到 `/Applications/Qbar.app`。检查浮窗时临时切换过“聚合浮窗”，之后恢复用户原来的“普通折叠”。
- 已知问题：本机“应用布局”尝试将搜狗输入法移入收纳区时，macOS 未接受移动；三个应用的分组设置保留待应用。不能把浮窗显示分组等同于物理菜单栏移动成功。
- 追加诊断：对 Docker Desktop 测试更换拖动事件目标后，系统曾将它移入错误的“始终隐藏”区域，反向拖动未成功。已撤回该实验性拖动变更，并暂停本机菜单栏管理，让 Docker 重新显示；三个待应用分组仍保存。正式版在落点验证失败时会自动暂停管理，避免错误区域继续遮住图标。最终 24 项测试通过，通用 Release 已重新安装；本机保持“普通折叠”、管理关闭、布局待应用。

## 刘海屏物理布局复查（2026-09-29）

- 测试图标 A 在分隔符位于刘海右侧时，可以通过更新后的事件序列向左移入收纳区；扫描确认其窗口进入两个分隔符之间。向右恢复的真实拖动仍失败，即使目标只在分隔符右侧 5 点处。因此不能将单向成功视为完整布局功能。
- 新应用启动会改变整个菜单栏的宽度和分隔符位置；静态预设分隔符位置在本机不可靠。已撤回实验中写死的分隔符位置，没有把它作为正式方案。
- `move` 现在在结束临时展开、菜单栏重新折叠后再次扫描并核对物理分组，避免“展开时看似成功，折叠后又回原位”的假成功；整批应用布局在任一步失败时自动暂停管理，保留用户分组设置。
- 本机正式版实测“应用布局”：目标分隔符进入刘海区域时弹出明确错误，管理自动关闭，三个待应用分组保留，菜单栏图标恢复。测试图标及实验产生的 WPS 规则已清理。
- 24 项配置与运行时测试通过；arm64/x86_64 Release 编译并通过签名校验，已安装在 `/Applications/Qbar.app`。物理反向拖动与拥挤刘海场景仍未通过验收，不应宣称完整 iBar 功能。
